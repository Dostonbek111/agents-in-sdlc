GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、開発者のマシンで行われているツール呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューして変更ごとに採用・取り消しを行い、エディターを離れずに追加プロンプトで会話を誘導できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッション中にエージェントを誘導し、ハイコントラストに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加要望がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードも切り替えられるようにします。新しい会話を始めるのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順、調査するファイル、実行するコマンド、提案する編集が表示されます。ファイル編集は差分と **Keep** / **Undo** 操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取り・編集や、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案したら、差分がインライン表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再試行させます。
4. チャット上部の **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出し (ターミナルコマンドの実行など) に権限が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。既存のチャットセッションを続けることで、エージェントは変更済みのコンポーネント、スタイルの方針、ローカルストレージの使用方法などを引き続き参照できます。

1. Copilot Chat の入力欄で、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが望まない方向に進んだ場合 (たとえば切り替え UI を意図しない形でリファクタリングする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、明確な追加指示を送ります。

> [!TIP]
> 進行中のセッションを誘導する方が、最初からやり直すよりも早く進められます。追加プロンプトで調整を依頼できます。たとえば「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3つ目の切り替えを追加せず、ライトモードを既存の設定パネルに組み込む」「両方の切り替えにキーボードショートカットも追加する」などです。

## 変更内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の保持など、カスタムエージェントのアクセシビリティ指針が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次の演習で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視・誘導しました。ファイル編集を確認しながら採用または取り消しを選び、会話のコンテキストを保ったまま追加プロンプトで作業を広げました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 追加プロンプトを使って、進行中のセッションを誘導しました。
